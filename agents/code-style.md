# Code Style

## Async Runtime

- Use Tokio: `#[tokio::main]` (multi-thread) in the CLI, `#[tokio::test]` in tests.

## Module Organization

- Split files when they acquire a second responsibility, not at a line-count threshold; keep cohesive types and their small private helpers together.
- Keep a struct and a large trait impl in separate files, e.g. `trezor-connect/src/ble.rs` (`BleBackend`) and `ble/backend_impl.rs` (its `ThpBackend` impl), with tests in `ble/tests.rs`.

## Trait Design

- Use native `async fn` in traits with `#[allow(async_fn_in_trait)]` on the trait (see `thp/backend.rs`).
- Use `#[async_trait]` only for traits used as `dyn` objects (`PairingController`, `ThpStorage`), since native async trait methods are not object-safe.

## Interior Mutability

- Prefer `parking_lot::Mutex` over `std::sync::Mutex` for synchronous state.
- Use `tokio::sync::Mutex` only when a guard is held across `.await`.

## Protobuf

- Proto files are vendored in `crates/thp-proto/proto/` and generated by `prost-build` + `protoc-bin-vendored` in `crates/thp-proto/build.rs`. Do not edit generated code.

## FFI

- UniFFI 0.32 with derive macros: `#[derive(uniffi::Object)]` on exported types and `#[uniffi::export(async_runtime = "tokio")]` on their impls (see `crates/hw-ffi/src/ble/workflow_api.rs`).
